## 1. 本次确认的核心原则

### 1.1 AI拆解成功不发送无动作价值的纯知悉提醒

AI拆解成功后，不因为“拆解成功”本身向创建人、主承办人发送纯知悉通知。

节点负责人分两类处理：

1. 节点负责人是主承办人本人：不需要再次确认承接，节点直接进入正常执行提醒流程。
2. 节点负责人是协办人：向该协办人发送“节点待承接”通知，由本人确认是否承接。只有确认承接后，才进入正常节点执行流程。

创建人、汇报对象、验收人、其他协办人、高管或管理员，不因为某个协办节点被生成而收到该节点的待承接通知。

### 1.2 未承接协办节点禁止发送执行类提醒

协办节点处于“待承接”期间，禁止发送任何暗示其已经承担执行责任的提醒，包括但不限于：

- 节点开始执行提醒；
- 节点临期提醒；
- 节点到期提醒；
- 节点逾期执行提醒。

执行类提醒的统一前置门禁为：

```text
node is effective
AND node owner relationship is valid
AND (
  owner == task.main_assignee_employee_no
  OR collaborator has explicitly accepted the node assignment
)
AND node is not completed/cancelled
```

因此，“节点时间已经到了”不能绕过承接确认。未承接时如果需要提醒，只能使用“待承接”类消息，不能使用“请开始执行 / 即将到期 / 已逾期”类消息。

## 2. 协办节点承接流程

```text
主承办人接受任务
    ↓
AI拆解成功并写入有效节点
    ↓
判断节点负责人
    ├─ 主承办人本人
    │    ↓
    │  无需承接确认
    │    ↓
    │  正常节点执行流程
    │
    └─ 协办人
         ↓
       仅该协办人收到“节点待承接”
         ↓
       协办人查看节点上下文
         ↓
       接受承接 / 无法承接
         ↓
       接受：进入正常节点执行流程
       拒绝：记录原因并进入后续责任处理流程
```

功能13实现时，节点承接状态必须由服务端权威保存和校验；前端按钮显隐不能代替后端权限。若当前物理表没有可复用字段承载协办节点承接状态，必须新增增量迁移并记录在功能13验收文档中，禁止通过 localStorage 或仅前端状态模拟。

## 3. 节点临期提醒时间算法

临期提醒不使用固定“统一提前24小时”，而是根据节点自身有效工作时段跨度动态计算。

### 3.1 节点跨度

```text
node_working_span =
working_time_between(
  task_nodes.planned_start_time,
  task_nodes.planned_deadline
)
```

必须复用项目统一工作时间口径；不得用 estimated_hours 或 task_nodes.estimated_hours 推导节点跨度。

### 3.2 临期提前量

```text
如果 node_working_span <= 1个工作日：
    due_soon_lead = 2个工作小时

如果 1个工作日 < node_working_span <= 3个工作日：
    due_soon_lead = 4个工作小时

如果 node_working_span > 3个工作日：
    due_soon_lead = 1个工作日
```

临期触发时间：

```text
due_soon_at =
subtract_working_time(
  task_nodes.planned_deadline,
  due_soon_lead
)
```

### 3.3 边界保护

- `due_soon_at`不得早于`planned_start_time`。
- 若计算后的临期时点与开始时点重合，应合并/去重，避免同一时刻连续发送“开始”和“临期”两条重复提醒。
- 已完成、已取消、已失效节点不生成临期提醒。
- 协办节点未确认承接时，即使到达`due_soon_at`也不得生成执行类临期提醒。
- 所有提醒由服务端根据当前节点状态重新校验后生成，历史 reminder_rule 到点不代表一定要发送。

## 4. 示例

### 示例A：一天内节点

```text
planned_start_time = 09:00
planned_deadline = 18:00
node_working_span <= 1个工作日
```

临期：截止前2个工作小时，即约16:00（以统一工作时间函数的实际结果为准）。

### 示例B：两天节点

```text
node_working_span = 2个工作日
```

临期：截止前4个工作小时。

### 示例C：五天节点

```text
node_working_span = 5个工作日
```

临期：截止前1个工作日。

## 5. 功能13实现与测试强制项

开发功能13时至少覆盖：

1. 主承办人本人节点不要求再次承接。
2. 协办节点仅节点负责人收到“待承接”通知。
3. 协办人确认承接前，开始/临期/到期/逾期执行提醒全部禁止。
4. 协办人确认承接后，执行类提醒才可根据节点时间规则生效。
5. 临期三档边界：1个工作日、超过1到3个工作日、超过3个工作日。
6. 临期计算不得依赖 estimated_hours。
7. 临期时间不得早于节点计划开始时间。
8. 已完成/取消/失效节点即使旧提醒到点也不得发送。
9. 同一节点、同一提醒类型、同一触发时点必须去重。
10. 通知点击后仍需重新执行任务可见权限、节点负责人关系和当前状态校验；通知本身不授予业务权限。
