## 一、此次只解决什么

用户反馈任务详情“接受任务”没有反应。原acceptTask()调用wx.showModal时使用5字符confirmText“接受并拆解”，超过官方接口的4字符上限，而且缺少弹窗自身的失败提示。扫描发现验收页的“通过并归档”同样为5字符。本次同时修复这两处同类问题。

官方依据：微信小程序官方api-typings的ShowModalOption（本轮在线核对，confirmText/cancelText最多4字符，并定义fail、complete回调）：
https://github.com/wechat-miniprogram/api-typings/blob/master/types/wx/lib.wx.api.d.ts

源码缺陷明确存在；但本环境不能获取用户设备Console，不能把受控模拟的失败结果冒充用户设备的实际报错。

弹窗失败时显示“确认窗口打开失败，请重试”，不调用业务接口。用户取消时不报错、不提交；再次点击能够打开。请求失败沿用原接口错误提示，不伪造成功、不跳转。接受成功仍进入原拆解状态页；验收成功仍按原逻辑归档并返回详情。

WXML中的页面按钮“通过并归档”保持原样；四字符限制针对原生弹窗参数，不是所有页面文字。未修改页面布局、样式、接口网关、mock仓库、认证、状态机或通知计算。
