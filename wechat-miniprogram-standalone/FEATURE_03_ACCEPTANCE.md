# 功能 03 验收单：任务详情

## 本批次开发边界

功能 03 只完成任务详情的真实读取、第二版页面还原和查看类交互，不提前实现后续功能的业务写动作。

- 页面与组件：以《02-第二版-智能任务看板前端.html》的任务详情为视觉、布局、弹层和交互基准。
- 业务字段与权限：以 PRD V1.1 的 TD-01～TD-12、TD-16、TD-18 为本批次验收依据。
- 接受/退回、节点完成、进度提交、生命周期、完成申请和验收等写动作仍按后续功能批次开发；本页不调用这些旧写接口。

## 已完成

- 第二版任务详情页头：返回、居中标题、更多操作。
- 白色任务摘要卡：任务名、编号、权重、状态和总体进度。
- 五模块吸顶标签：概览、人员、节点、进度/汇报、绩效；支持点击定位、滚动同步高亮和标签左右滑动定位。
- 任务轨迹：覆盖未开始、进行中、受阻、待汇报、待验收、已完成，并兼容 V1.1 拆解中/拆解失败和终止态说明。
- 基本信息：节点数、编号、开始/截止、进度、权重、剩余时间、优先级、完成时间、突发性和系统实际工时。
- 任务背景、目标、来源和文字交付说明；不展示预计工时，不提供附件入口。
- 人员信息：创建人、主承办人、验收人、汇报对象和任务级协同人。
- 节点折叠卡：节点顺序、动作、状态、进度、负责人、协同人、时间、完成情况、依赖、资料、文字成果和卡点提示。
- 从任务概览节点卡或工作台支持事项携带 `nodeId` 进入详情时，自动展开并定位对应节点。
- 最新进度汇报：进度、阶段成果、卡点、备注、汇报人和时间；缺失字段显示“无”。
- 绩效关联：只展示已确认绩效匹配；无正式确认时展示未关联空态。
- 403、404、网络/服务错误使用独立页面状态，不把无权限伪装成无数据。
- 操作记录底部抽屉：状态日志和任务审计日志按任务查看权限读取并分页加载。
- “更多操作”底部抽屉：本批次仅提供真实的复制任务编号；未开发写动作不显示假成功入口。
- 详情页恢复第二版底部导航，任务入口保持选中。

## API 读取契约

API 模式进入任务详情时组合读取：

- `GET /api/v1/tasks/{taskId}`
- `GET /api/v1/tasks/{taskId}/available-actions`
- `GET /api/v1/tasks/{taskId}/status-logs`
- `GET /api/v1/tasks/{taskId}/progress-reports`
- `GET /api/v1/tasks/{taskId}/issues`
- `GET /api/v1/tasks/{taskId}/operation-logs`

新增的任务级审计日志接口先执行任务查看权限校验，再返回分页记录；没有新增数据库迁移。

## 微信开发者工具重点验收

1. 从工作台/任务概览进入任意任务，检查页面结构与第二版详情一致。
2. 点击五个标签并上下滚动，检查模块定位及高亮同步。
3. 在“我的节点任务”点击节点卡，确认进入详情后自动展开目标节点。
4. 展开节点，检查负责人、协同人、时间、依赖、卡点、资料和文字成果。
5. 查看最新汇报和绩效模块的有数据/空态。
6. 点击“查看操作记录”，检查抽屉和加载更多。
7. 点击右上角更多，确认复制任务编号真实可用。
8. 确认详情页不存在预计工时展示，且功能 07～11 的写动作没有被本批次提前接通。
