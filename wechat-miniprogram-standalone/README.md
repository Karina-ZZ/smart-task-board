# 旺序AI任务中枢｜微信原生小程序 V1.1

这是一套可直接导入微信开发者工具的原生小程序代码。默认使用本地演示模式，不需要 npm、数据库、企业微信参数或 AI Key。

## 当前验收阶段

本代码包目前完成并开放验收的是功能 01、功能 02 和功能 03。

功能 01“员工任务工作台”包括：

- 问候、日期、消息入口和个人入口；
- 一句话创建任务、文字草稿保留、录音入口和非空校验；
- 进行中、未来 3 天临期、近 90 天按期完成率；
- 任务风险四象限筛选和清除；
- “需要我支持”待响应事项；
- V1.1 七种任务状态筛选、任务卡片和全部任务入口。

功能 02“任务/节点概览”包括：

- 五类状态概览卡与状态快捷筛选；
- 主任务、我的节点任务两种模式；
- 完整状态、四象限、未来 3 天临期、需要支持、开始日期、搜索和排序；
- 筛选摘要、重置、空态、错误重试和加载态；
- 服务端分页、节点定位详情、筛选及滚动位置恢复。

功能 03“任务详情”包括：

- 与第二版前端一致的白色摘要卡、五模块锚点、任务轨迹和底部操作区；
- 基本信息、任务背景/目标/来源/文字交付说明和系统实际工时只读展示；
- 创建人、主承办人、验收人、汇报对象和协同人；
- 节点折叠、负责人/协同人、时间、依赖、卡点、资料和文字成果；
- 最新进度汇报、已确认绩效关联及对应空态；
- 状态日志 + 任务审计日志的操作记录抽屉和分页；
- 任务概览节点卡/工作台支持事项携带 `nodeId` 后的节点自动定位；
- 403、404、请求失败独立状态；不展示预计工时。

功能 03 只验收详情读取和查看交互；接受、节点完成、进度提交、生命周期和验收写动作按后续功能批次接通，不在本批次提前实现。

仓库内除功能 01～03 外的其他页面用于保证已完成页面跳转后不出现空路由，尚不代表其已完成逐项验收；后续会按功能批次继续完善和交付。

## 直接运行

1. 安装并打开微信开发者工具。
2. 选择“导入项目”。
3. 项目目录选择本文件所在的 `wechat-miniprogram` 文件夹。
4. AppID 可先使用测试号；本项目 `project.config.json` 已配置 `touristappid`。
5. 点击“编译”。默认首页是员工工作台。

本阶段体验建议：

1. 在蓝色 AI 输入区输入任务描述，退出再进入工作台，确认草稿仍保留。
2. 点击任一风险四象限，确认页面滚动到任务区并叠加筛选；点击“清除”。
3. 横向切换七个状态标签，检查空态和任务卡片。
4. 点击“需要我支持”事项、任务卡片、消息和头像，检查跳转。
5. 下拉页面，检查工作台数据刷新。

任务概览体验建议：

1. 点击顶部五类状态卡，确认结果同步筛选。
2. 切换“主任务 / 我的节点任务”，检查卡片信息和详情定位。
3. 通过“更多筛选”组合状态、四象限、临期、日期与排序。
4. 进入详情后返回，检查筛选和滚动位置恢复。
5. 在工作台点击“全部任务”，检查临时筛选被清空。

任务详情体验建议：

1. 点击五个详情标签并上下滚动，检查概览/人员/节点/进度汇报/绩效的定位与高亮。
2. 从“我的节点任务”进入详情，检查对应节点自动展开并定位。
3. 展开节点，检查负责人、协同人、起止时间、依赖、卡点、资料和文字成果。
4. 查看最新汇报、绩效关联和空态；确认页面不显示预计工时。
5. 打开“操作记录”检查抽屉和分页；打开右上角更多，检查复制任务编号。

## 连接 FastAPI 后端

修改 `config.js`：

```js
module.exports = {
  mode: "api",
  apiBaseUrl: "https://你的可信域名",
  requestBodyCase: "snake_case",
  requestTimeoutMs: 12000,
  timezone: "Asia/Shanghai",
};
```

再完成三项运行配置：

- 在微信公众平台配置 request 合法域名，必须使用 HTTPS。
- 登录后把 Bearer access token 写入 `wangxu.accessToken`；正式环境应替换为企业微信 OAuth/小程序登录换票流程。
- 后端按 V1.1 提供创建发送、接受后拆解、重试、高管聚合及负荷下钻接口。当前仓库已有查询、节点、汇报、问题、验收等基础 API；小程序数据网关集中在 `utils/api.js`，便于逐项联调。

生产模式不会提供身份切换、数据重置或虚假成功反馈。服务器错误会保留错误信息并阻止页面误报成功。

```text
  app.*                    # 应用入口与第二版全局视觉

  pages/workbench/         # 功能01：员工任务工作台
  pages/tasks/             # 功能02：任务/节点概览

  utils/api.js             # 统一API与错误入口
  utils/store.js           # 本地验收数据与V1.1状态机
  tests/                   # 主链路与静态契约测试
```

## 功能05：云函数AI配置

任务字段识别/追问使用可替换的独立 ChatService。重新部署云函数后只需修改 `config.js`：

```js
cloudServices: {
  loginServiceBaseUrl: "https://your-login-service.example.com",
  chatServiceBaseUrl: "https://your-chat-service.example.com",
}
```

Qwen Key、MySQL密码和JWT Secret只放云函数环境变量，不放小程序。

## 功能06：创建人三步创建

创建人流程固定为“描述任务 → 信息确认 → 确认发送”。信息确认页真实保存任务级草稿，人员与绩效选择均接真实API；确认发送后只进入待接受并仅通知主承办人，不生成正式节点。

## 功能13：通知、节点承接与待处理

- AI协办节点生成后，只向对应协办人发送“节点待承接”；主承办人本人节点无需再次确认。
- 协办人未接受前不能开始/完成节点，也不会收到开始、临期、到期、逾期执行提醒。
- 节点临期按有效工作跨度动态提前2工作小时/4工作小时/1工作日，不使用预计工时。
- 通知点击按后端返回的当前 `targetType` 跳转；节点待承接会定位对应节点并显示真实“接受承接/无法承接”动作。
- 通知红点表示“待处理”，生产环境不提供“全部已读”、身份切换或重置演示数据。
- 累计 `npm test` 已串联功能01～13共16个测试文件。
